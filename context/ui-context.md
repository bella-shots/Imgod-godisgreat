# UI Context

## Product direction
The portal should be simple, clear and functional rather than attempting to reproduce a full visual website builder.

## Google Site structure
- HOME
- PROJECTS
- FINANCE
- HR
- REPORTS

## UX principles
- Clear navigation
- Minimal visual clutter
- Consistent naming
- Easy access to permitted workflows
- Clear distinction between viewing information and submitting information
- Avoid exposing sensitive source data through broad embeds
- Mobile usability should be considered during Phase 5

## Project view
A project may expose:
- event/countdown information
- permitted checklist information
- permitted expense information
- MOM references
- notes
- project files
- project reports

Sensitive source information must remain restricted even when project information is surfaced through the portal.

## Status language
Use explicit states such as:
- Draft
- In Progress
- Submitted
- Pending
- Approved
- Rejected
- Published
- Updated
- Completed
- Failed

## Design constraint
Do not introduce a custom drag-and-drop visual builder unless a future architecture decision explicitly requires it.
