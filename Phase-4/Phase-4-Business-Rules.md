## R52 — Explicit Generate-ID controls for Sheet-originated records

## R56 — Frozen one-click Employee creation
- Employee creation is finalized by one explicit **Generate Employee ID** action after the pending row is completed.
- Before issuing an Employee_ID, the workflow validates the complete required employee record and duplicate email constraints.
- On success, the workflow invokes A4-00, writes and locks the canonical EMP-000001-style Employee_ID, stamps Created_At, and finalizes the record in the same controlled workflow.
- A separate Save/Process action is not part of the frozen Employee creation contract.
- Employee_ID must never be generated by generic onEdit, autosave, spreadsheet-open, or passive cell-edit behavior.
- Validation failure must prevent ID issuance and finalization. An issued ID is never reused.

- For Project_Members, Project_Notes, Budget_Given and Salary_Admin, ID generation is explicitly user/system initiated through the designated Generate-ID control. Generic onEdit/autosave events must never issue a business ID. The generator validates the pending row, serializes issuance with LockService, writes the ID, locks the ID field, and only then permits commit/save. Salary supports controlled bulk generation for validated payroll imports/entries. Employee_ID retains its frozen dedicated workflow.

## R57 — Universal explicit Generate-ID rule for user-created Sheet records
- Every user-created authoritative Sheet record that requires a business ID must have one explicit Generate-ID action as its controlled creation/finalization entry point.
- The action validates the pending record, checks applicable duplicate/identity constraints, invokes A4-00, writes and locks the canonical business ID, and performs the appropriate authoritative commit/finalization.
- Generic onEdit/autosave/passive cell-edit/spreadsheet-open behavior must never issue a business ID.
- The common user interaction is: **select pending record → explicit record-specific Generate-ID action → validate → generate via A4-00 → persist/lock ID → commit/finalize**.
- This applies to directly user-created Sheet records requiring business IDs, including Employee, Project Member, Project Note, Budget, Spending, OOP Claim, Salary and Investment records.
- Salary may use one explicit controlled **Generate Salary ID(s)** action for a validated bulk import/entry batch.
- Form/system-generated IDs remain automatic. This includes IDs created during controlled Form-processing workflows and Submission_ID generated by the system/index.
- No separate Save/Process action is required solely to complete a R57 Generate-ID transaction.
- A4-14 is the shared implementation pattern; individual modules retain record-specific validation and business rules.
- A4-00 remains the sole authoritative generator and all R49/R52/R56 stability, locking, reconciliation and no-reuse rules remain mandatory.
